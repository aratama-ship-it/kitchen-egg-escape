# 厨房脱出：卵が9区画を抜けるまで

**公開URL: https://aratama-ship-it.github.io/kitchen-egg-escape/** （スマホで開ける）

床すれすれの後方視点で、卵を撞いて転がし、厨房の裏口を目指すブラウザゲーム。
卵は押せない。**ゴルフの一打のように前へ振り出すと、中の黄身が殻の内壁を蹴り、
その反動だけで卵が転がる。**一打ずつ進めながら裏口を目指す。
9区画あり、割れたらその区画の最初からやり直す。

## 起動

```sh
npm install
npm run dev
```

表示されたURL（既定では `http://localhost:5173/`）を開く。

## 操作

**前へ振り出して、放す。** 振り出した長さが力になり、
床に伸びる黄色い帯で飛距離の見当がつく。斜めに振れば、その分だけ曲がる。

手前へ引いても卵は戻らない。ゴルフと同じで、一打は常に前への一打になる
（手前寄りに振ると横向きの一打、真後ろへ振ると空振りで一打にならない）。

- スマホ／PC：前へ振り出して、放す
- PC補助：矢印キー上（まっすぐ）／左右（斜め前）
- `R`：いまの区画を最初からやり直す
- `Esc` または画面右上の「タイトル」：タイトルへ戻る
- `Enter`：区画を抜けた画面から次へ進む
- 開発サーバーのみ `B`：破壊演出を即時確認する
- 開発サーバーのみ `N`：いまの区画を即クリアする
- 開発サーバーのみ `C`：猫をすぐ呼ぶ
- 開発サーバーのみ `?stage=3`：3区画目から開く

放すと黄身に速度が与えられ、殻の内壁へぶつかる。そこで失われた運動量がそのまま殻へ渡り、
卵が動き出す。**卵に直接力を加えている場所はコード上に一つもない。**

一撃で進むのは約0.38 m（卵6個ぶん）。転がり終わるまで約1.7秒で、そこから次を撞ける。
待たずに撞き足すこともできるので、転がっている卵をさらに押し出すこともできる。

**前へ撞いても外れない角がある。** 障害物の角に噛んだときは、同じ向きへ撞くかぎり抜けられない。
横（障害物と反対側）へ撞けば必ず外れる。2回続けて進めないと画面下に「横へ狙う」と出る。

## 区画ごとに卵が変わる

区画が進むほど卵は小さくなる。これは見た目だけの違いではなく、転がり方そのものが変わる。
大きい卵は1 mあたりの回転数が少なく、ゆっくり重く転がり、多少ぶつけても割れないが、
狭いところを通れない。小さい卵は速く回り、脆く、細い隙間を抜けられる。

寸法は倍率、質量は倍率の3乗、速度は倍率の平方根で決まる（`src/egg-types.js`）。
撞く強さ、割れる境目、通り抜けに必要な幅も、すべて同じ換算表から出している。

基本はニワトリの卵で、1区画目だけダチョウの卵にしてある。
`src/stages.js` の各区画の `egg` を書き換えれば、どの卵にも差し替えられる
（通り抜けられるかはテストが確かめる）。

| 区画 | 卵 | 長径 | 質量 |
|---|---|---|---|
| 1 仕込み台の下 | ダチョウ | 19 cm | 1620 g |
| 2〜5 | ニワトリ | 6 cm | 60 g |

## 猫と逃げ場

2区画目から猫が現れる。低いうなりのあと、**前足が横から降りてきて**卵を弾く。
床に落ちる影が濃くなっていくのが、手が近づいている合図になる。

予告から一撃までは1.15秒。全力の一打は1.1秒で0.37 m動けるので、
反応が間に合えば逃げ切れるが、考えている猶予はない。猫は4〜8秒おきに来る。

**前足は予告した瞬間の場所を狙う。**床に出る影がその範囲で、そこから出れば空振りする。
全力の一打なら1.6秒で0.37 m動けて逃げ切れるが、弱い一打の0.16 mでは届かない。
本気で撞くか、隙間へ入るか。どちらもしなければ当たる。

弾かれる向きは、**猫のいる側の反対**を軸にばらつく。どこへ飛ぶかは読めないが、
どちらから来るかは見えている。理不尽だが、避ける手はある。

床に緑の縁で囲まれた場所が**隙間**で、そこにいるあいだは前足が届かない。
予告が出てから前足が入るまでは約1.1秒。間に合う位置にいるかどうかが判断になる。

一撃で**1.4〜1.5 m 弾かれる**（一打で進むのは0.38 m なので、4打ぶんほど戻される）。
このとき床への落下は0.53 m/s で、割れる境目の1.0 m/s には届かない。
つまり猫では割れないが、進みは大きく損なう。

## 行き交う人

4区画目「配膳ラッシュ」では、厨房のスタッフが通路を歩き回る。床すれすれの視点では、
巨大な靴と脚が交互に降りてくる森になる。

- **降りてくる靴に踏まれたら、その場で割れる。**卵がどれだけ静かにしていても関係ない
- 床に落ちる**丸い影が、次に靴が降りる場所**。濃くなるほど着地が近い
- 接地している靴は革のつま先。軽く触れる・押されるだけなら割れず、
  **全力の一打で突っ込んだときだけ**割れる（通常の障害物の4倍の速さまで許される）
- 足音は距離で大きさが変わる。近い足音は、見えていない足の気配になる

歩き方は `src/stages.js` の `walkers` にデータとして書いてある。足の位置は時刻から
決定的に計算され、描画・剛体・通過検証がすべて同じ計算を使う。

## 抜けた床と段差

6区画目「排水溝」では床そのものが抜けている。`src/stages.js` の各床区間に
`slots`（抜けている x の範囲）と `level`（床の高さ）を書ける。

- **渡り板**: 溝を渡れるのは幅0.30 mの板一枚だけ。外せば落ちる
- **段差**: 渡った先は0.12 m低い。実測で落下0.80 m/s、割れる境目1.00 m/sの内側
- **格子**: 進行方向に走るスリット。桟（幅0.40 m）から外れれば落ちる

### 平らな段差は技量が効かない（実測）

当初は「勢いよく落ちると割れる」段差を考えたが、測ると成立しなかった。
落下速度は**落差だけで決まり、助走の強さはほぼ関係ない**。

| 段差 | 弱く撞く | 普通 | 全力 |
|---|---|---|---|
| 14 cm | 無事(0.91) | 無事(0.90) | 無事(0.93) |
| 18 cm | 割れた(1.02) | 割れた(1.04) | 割れた(1.07) |

どう撞いても結果が同じでは選択にならないため、段差は「落ちる先」として使い、
**技量を問うのは渡り板と格子**に任せている。

また、幅0.15 mの溝を跳び越える案も測ったが、全力でも届かなかった。
卵は跳ぶのではなく転がり落ちるため、この操作系に「跳躍」は無い。

## ベルトコンベア

6区画目「洗浄ベルト」の中央には、手前へ流れる帯がある。乗っているあいだ、
床そのものが卵を運ぶ。**撞かずにいると押し戻される。**

実測での違いは次のとおり（一打あたりの前進）。

| | 一打あたり |
|---|---|
| ベルトの上で上流へ撞く | +0.10 m |
| 脇の通り道を行く | +0.36 m |

押し切って渡ることもできるが、脇を回るより3倍以上遅い。
区画の奥には**横へ流す帯**もあり、そちらはまっすぐ撞くと流されるので、
上流へ向けて狙う必要がある。
猫の逃げ場は左右にあるので、「急いで脇へ寄る」判断がそのまま安全にもつながる。

帯は `src/stages.js` の `belts` にデータとして書く。床と卵の速度差に比例した
引きずりなので、流れの速さに追いついたらそれ以上は押されない。

## 細い区画と、視界の悪さ

6区画目「配管の裏」は通路の幅を標準の6割（片側0.70 m）に絞り、霧の届く距離を
1.5 mまで詰めてある。**一打ぶん先までしか見えない**ので、次の仕切りは見えるが
その先は闇になる。暗い区画では、透けた殻ごしに黄身の色が足元を弱く照らす
（`atmosphere.eggLight`）。

仕切りは左右交互に張り出すが、**行き止まりは作らない**。一打は前方限定なので、
引き返しが必要な構造を置くとその時点で詰みになる。必ずどちらかの側が空いている。

視界は `atmosphere` の `near` / `far` で区画ごとに決める。

## 現在の物理モデル

- Rapierの3D剛体を120 Hzの固定刻みで計算
- 高さ64 mm、最大幅約47 mmの卵形を、描画形状と590点の凸包コライダーで共有
- 殻8 g、黄身52 g、合計60 g
- 黄身が内壁へ達したときの運動量を殻へ渡す。撞く力はここだけから生まれる
- 蹴られた勢いは、床のグリップに応じて転がりへ変わる。滑る床では滑ったまま進む
- 卵は**横倒し**で置く。立てて置くと、倒れたあと長軸が進行方向を向いて転がらなくなる
- 重力、接触、摩擦、反発、慣性、連続衝突判定を物理エンジンで計算
- 黄身はばね・減衰を持つ「移動する内部質量」とし、毎ステップ合成重心と慣性へ反映
- 殻に約1.8%の微小な非対称を持たせ、横ずれを任意の蛇行スクリプトではなく接触形状から発生させる
- 床以外への一定以上の衝突を接触力イベントで検出し、殻を破壊する
- 重力を1/3にして、**3倍の大きさの世界と同じ運動**にしている。見え方は変えずに、
  転がりが大きなものらしくゆっくりになる（毎秒1.5回転。等倍だと毎秒2.5回転で速すぎた）
- そのうえで時間を1.2倍で進める

詳しい前提と、実測で分かったことは [PHYSICS_MODEL.md](./PHYSICS_MODEL.md) を参照。

## 画角

卵は常に画面の中央に置く。縦画面ではカメラの横の視野が片側14度ほどしかないため、
少しでも横に流れると枠外へ出て操作できなくなる。

**カメラの高さは卵ではなく床を基準にする。**段差のある区画で卵の高さだけを見ていると、
一段下りたときにカメラが上の床に埋もれて前がまったく見えなくなる。前後の床のうち
一番高いところより必ず上へ置き、注視点は「これから転がっていく床の高さ」に合わせる。
固定の高さを見ていると、下りたときに上を向いてしまい足元の先が見えない。



止まっているあいだと打っているあいだで、卵の画面上の位置を変えている。
タイトルや結果の画面では文字組みと釣り合う高さに置き、打ちはじめると卵が下へ下がって、
その先の床が広く見えるようになる。切り替えは0.3秒ほどかけて滑らかに移る
（`TITLE_FRAMING` と `PLAY_FRAMING`）。

## 割れる演出

障害物へ強く衝突すると、短い閃光と乾いた音の後、殻片が床へ落ち、白身と黄身がその場に残る。
結果表示は約1.5秒待ってから「割れた。」「厨房は、止まらない。」だけを出し、派手な失敗演出にしない。

**跳ねすぎても割れる。** 連打で跳ね続けると、床へ落ちてくる速さが上がる。
落下速度が1.0 m/sを超えると、障害物に当たらなくても着地で割れる
（「跳ねすぎた。」と出る）。通常の転がりでは0.29 m/s、速い連打でも0.67 m/sなので、
普通に打っているかぎり当たらない。

通常の床接触や、ごく弱く壁をこする動きでは割れない。現在の判定値はゲーム用の初期調整で、
実物の殻強度を測定した値ではない。

`.gitignore` で公開対象から外している（消してはいない）。

## テスト

```sh
npm test
npm run build
```

29本。卵形状、黄身のばね・慣性・制御則、破壊判定に加えて、区画については次を確認する。

- すべての区画で床が隙間なく敷かれ、通り抜けられる幅が残っている
- **素直に狙って撞くだけで、5区画すべてを実際に完走できる**（Rapierで通しで撞いて確認）
- 卵はどの区画でも横倒しで床の上から始まる
- 濡れた床では、同じ一撃でも転がらず滑るため、乾いた床より横へ曲がらない
- 換気扇の風が、火口のある側へ卵を引く
- カートは開始時に通路の中央を塞がず、壁ぎわに待避場所が残る

通過確認は `tests/stage-traverse.test.js` の操作モデルが行う。
これは「うまい人」ではなく「素直に隙間を狙うだけの人」を模しており、
ここで通れない区画は設計として通れないものとして扱う。

## 既知の課題

- 一撃0.38 mに対して区画が3.6〜5.0 mあるため、1区画あたり10打前後かかる。
  短くしたい場合は `src/stages.js` の `length` を下げる（障害物のzも合わせて動かす）。
- 黄身の速度を上げすぎると重心の移動が速すぎて計算が荒れるため、撞く力に上限がある。
- 角に噛んだときは横へ撞けば必ず抜けられるが、それを画面の文字で伝えている。
- 実物の卵を転がした映像・計測値とのキャリブレーションはまだ行っていない。
- 音は割れる音と区画通過の二音のみ。BGM・環境音はない。
